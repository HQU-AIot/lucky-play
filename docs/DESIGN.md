## 1. 形式（6 种）

1. **wheel 转盘**：Canvas 绘制 8 扇区，指针在 12 点方向，扇区边界经过时指针弹性摆动 + tick 声。
2. **grid 九宫格**：3×3，周围 8 格为奖品/谢谢参与，中央"开始"按钮；高亮圈逐格跳动。
3. **blindbox 盲盒**：3 只盒子先出现，点选其一，盒子蓄力摇晃后爆开，奖品弹出。
4. **flip 翻牌**：8 张背面朝上的卡牌，**翻开哪张哪张就是一次真实抽奖**（服务端扣库存）；其余牌依次翻开，显示按当前概率真实采样的奖品分布（`/api/sample`，无副作用），让全场是"真实的可能性"。
5. **slot 老虎机**：右侧拉杆启动（拉下回弹动画，支持键盘），三滚轮错峰停定（各自独立减速 + 滚动模糊），结果先行——三格内容在落定前替换为中奖奖品，每列停定回弹，全部停齐机身震动 + 顶灯跑马 + 停格亮灯。
6. **gacha 扭蛋机**：大机身（玻璃球舱满舱彩球 + 反光、出货口、投币口、品牌牌、顶灯），转旋钮 720° → 球舱抖动彩球跳动 → 扭蛋掉落弹跳 → 摇晃蓄力 → 壳盖旋飞、奖品 spring 弹出。

所有形式共用同一套结果流：**先请求 `/api/draw` 拿到结果 → 动画精确滑向该结果 → 结果弹窗**。

## 2. 主题（6 套，方向稿）

## 3. 动画规范（调研结论落地）

来源：MDN cubic-bezier / GSAP Eases / Ant Design motion / easings.net（原理性结论，无时效问题）。

1. **结果先行**：服务端先出结果，动画只负责"精确到达"——杜绝"转过了再修正"的突兀。
2. **转盘**（总长 4.0s，rAF 驱动，对齐音乐"停"）：蓄力回拉（-15°，0.40s ease-in）→ 爆发加速 → 长减速（easeOutExpo，3.22-3.30s）→ 过冲回摆（+2.9°，0.34s）。全程 transform:rotate（GPU）。
3. **指针仪式感**：每经过一条扇区边界，指针弹性下压回弹（CSS transform 弹簧）+ WebAudio 合成 tick 声（无需音频素材）；减速期 tick 间隔自然拉长，这是"越来越紧张"的来源。
4. **九宫格**：步进间隔按 2.2 次幂曲线拉长（快→慢），走灯总时长归一化为 3.25s（与结果格远近无关，解曲线系数），停格脉冲 0.75s；中奖格持续呼吸灯。
5. **盲盒**：盒子长蓄力摇晃（2.6s，振幅渐增、频率渐快）→ 盖子弹飞 + 纸屑迸发 → 奖品 spring 弹出（easeOutBack 过冲），开盖后展示到 4.0s 整。
6. **翻牌**：rotateY 3D 翻转（perspective 1200px，翻面 0.7s）；虚晃三连（每张 0.66s 抬起 + 0.22s 间隔，共 2.64s）→ 主牌蓄力呼吸 0.66s → 主牌翻开恰在 4.0s；其余牌在结果揭晓后依次翻开展示真实采样分布。
7. **老虎机**：三滚轮错峰启动（140/330/520ms）、各自 easeOutCubic 减速（1.9/2.4/2.9s），高速期滚动模糊（blur 2px），逐格 tick；结果先行——落点格内容提前替换为中奖奖品。滚轮视觉位置对条带长度取模循环，杜绝空白窗口；每列停定回弹 240ms，末轮停齐后补齐到 4.0s 时机身震动 + 顶灯跑马 + 停格闷响。
8. **扭蛋机**：旋钮 1080° 旋转（2.2s）+ 球舱抖动 + 彩球跳动 + 哒哒声 → 扭蛋掉落弹跳（0.55s，scale 挤压反馈）→ 摇晃蓄力（0.5s）→ 4.0s 整壳盖旋飞、奖品 spring 弹出 + 原地彩带迸发。
9. **结果弹窗**：spring 缩放进场 cubic-bezier(0.34,1.56,0.64,1)；中奖 → 全屏彩带（canvas 物理粒子：重力/阻力/旋转）+ 胜利琶音；谢谢参与 → 灰白纸屑小概率飘落 + 温柔双音，不嘲讽。
10. **可访问性**：`prefers-reduced-motion` 时全部动画压缩为 ≤400ms 淡入淡出；动画期间禁止重复点击。

### 3.5 音乐时间轴（《中奖概率倍儿高》，8.04s 整曲）

素材：`web/assets/lucky-song.mp3`（碎碎冰翻唱，响度分析确认 4.0s 处为"停"的尖峰，~5s"没中"，7.2s 起哭声）。
共享常量 `web/js/music.js`：`RESULT_AT = 4.0`。

- **起播**：`/api/draw` 返回（结果到手）的瞬间起播并与动画同时开跑——点击到起播仅有本机 API 延迟（~20-50ms），音乐与动画严格同相。
- **没中**：4.0s 各玩法落定结果、弹窗出场，歌继续唱"没中"+哭声直到 8.04s 自然结束（此时默认"谢谢"合成音效让位，不叠加）。
- **中奖**：4.0s 出结果，让"停"喊完整后延迟 ~0.3s、以 ~0.2s 淡出收歌（歌止 ~4.5s，赶在 4.9s"没中"之前），切胜利琶音 + 彩带。
- **快速再抽**：上一首未结束就开新一轮 → 从 0 重启。
- **开关**：工具栏 🎵 独立于 🔊 音效开关，localStorage（`lucky.music`）持久化；`prefers-reduced-motion` 实时读取、不播音乐（动画走各自的快速路径）；自动播放被策略拒绝时动画照常走自有时钟。

## 4. 概率模型（谢谢参与动态转移）

每个奖品：基础权重 `W_i`（后台可改）、总库存 `S_i`、剩余 `R_i`；谢谢参与基础权重 `W_0`。

| dynamic 模式 | 奖品有效权重 | 谢谢参与有效权重 |
| --- | --- | --- |
| `off` 关闭 | `W_i`（`R_i>0`），否则 0 | `W_0` |
| `per_win` 每抽一件渐移（默认，字面语义） | `W_i × R_i / S_i` | `W_0 + Σ W_i × (1 - R_i/S_i)` |
| `depleted` 抽空才整移 | `W_i`（`R_i>0`），否则 0 | `W_0 + Σ_{R_i=0} W_i` |

- `per_win`：每抽走一件奖品，该奖品"一份"的概率即时让给谢谢参与，库存抽空时恰好整体转移完。总概率质量恒定，只做再分配。
- 后台改动基础权重/补货即时生效；补货会让已转移概率自动"回流"（公式由库存推导，无漂移）。
- 已接受的瞬态偏差（2026-09-26 审查确认）：权重基于事务外快照，若并发请求恰逢某奖品被抽空的同一瞬间，该单抽按快照权重计算、偏差下一抽自愈（默认权重 ≤0.6pp，微秒级窗口，单机 kiosk 可忽略；详见 `app/store.py` `draw()` 文档字符串）。

默认权重（后台可改）：棒棒糖 30 / 奶龙 20 / 笔记本 15 / 书签 10 / 鲨鱼匕首 8 / 电子爬宠 6 / 手柄 2 / 谢谢参与 9（合计 100）。

## 5. 接口

公开：
- `GET /api/prizes` —— **剩余奖品查询接口**：`{event, prizes:[{id,name,emoji,remaining,total}], total_remaining}`
- `POST /api/draw` —— 抽奖：`{result:"prize"|"thanks", prize:{...}|null}`
- `GET /api/sample?count=7` —— 按当前概率独立采样展示结果（无副作用、不扣库存），供翻牌旁位展示
- `GET /api/meta` —— 活动名 / 日期 / 主题无关信息

后台（请求头 `X-Admin-Token`，token 见 README）：
- `GET /api/admin/state` —— 权重/库存/配置/有效概率/统计
- `PUT /api/admin/weights` —— 批量改权重 + 谢谢参与权重
- `PUT /api/admin/stock` —— 补货/改库存
- `PUT /api/admin/dynamic` —— 动态转移开关 + 模式
- `PUT /api/admin/event` —— 活动名/日期
- `GET /api/admin/history?limit=` / `POST /api/admin/history/reset`

## 6. 技术栈

后端 Python 3.11+ / FastAPI / SQLite（uv 管理）；前端零构建原生 ES Modules + Canvas + CSS 变量主题系统（离线可用，无 CDN）。
