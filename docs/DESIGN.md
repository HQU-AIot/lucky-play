## 1. 形式（2 种）

1. **wheel 转盘**：Canvas 绘制 8 扇区（7 奖品 + 谢谢参与，**不含手柄**），指针在 12 点方向，扇区边界经过时指针弹性摆动 + tick 声。
2. **slot 老虎机（对对碰，2026-09-29 改版）**：右侧拉杆或"开抽"启动，三滚轮错峰停定（各自独立减速 + 滚动模糊），结果完全由服务端决定——三轴符号组合先行定好，滚轮只是"精确到达"。轴面符号 = 各奖品 + 💎钻石（代替谢谢参与）。连线规则：全不同=没抽到；两同=该奖品×1；三同普通=该奖品×2；三同手柄=手柄+任选一件其它奖品；三同钻石=超级大奖（除手柄外每类有库存奖品各×1）；两同钻石=**中奖者现场自选**：弹出奖品方格（只列有库存的非手柄奖品），点选→「确认领取」两步防误触，再点已选的可取消重选，确认那一刻服务端事务才扣库存、写流水（一次性凭据防重复领取）。
   超级大奖与多奖品中奖在结果弹窗里以方格 chips 排列展示（"全是你的！"）。

所有形式共用同一套结果流：**先请求 `/api/draw` 拿到结果 → 动画精确滑向该结果 → 结果弹窗**。

## 3. 动画规范（调研结论落地）

来源：MDN cubic-bezier / GSAP Eases / Ant Design motion / easings.net（原理性结论，无时效问题）。

0. **版式**：抽奖舞台无卡片框（游戏直浮在主题背景上，更沉浸）；整页 body 纵向 flex 恰好一屏（顶栏+弹性舞台铺满视口，无上下大块留白、不滚动）；顶栏标题 clamp(28px, 4vw, 44px)；转盘 `min(860px, 94vw, 76vh)`（中心钮 15% 随盘缩放、窄屏固定 72px，扇区文字按最长名 canvas 实测宽度自适应、上限 0.05×盘径，绝不与钮/emoji 相交）、老虎机机身 `min(1160px, 94vw, calc(100vw - 268px))`（竖排提示锚定机身左侧留白）。

1. **结果先行**：服务端先出结果，动画只负责"精确到达"——杜绝"转过了再修正"的突兀。
2. **转盘**（总长 5.0s，rAF 驱动，对齐音乐"停"）：蓄力回拉（-15°，0.40s ease-in）→ 爆发加速 → 长减速（easeOutExpo，约 4.26s）→ 过冲回摆（+1.1°，0.34s；原 2.9°，2026-09-30 按需求调小）。全程 transform:rotate（GPU）。指针为实体造型（accent 圆钮 + 锥尖），每跨扇区弹簧抽打（scaleY 压扁回弹）；全主题转盘中心保持圆形。
3. **指针仪式感**：每经过一条扇区边界，指针弹性下压回弹（CSS transform 弹簧）+ WebAudio 合成 tick 声（无需音频素材）；减速期 tick 间隔自然拉长，这是"越来越紧张"的来源。
4. **九宫格（已移除）**：3×3 全 9 格走灯环线（外圈+中心收尾）、步进间隔按 2.2 次幂渐增停格，2026-09-29 按需求移除（规格见 git 历史）。
5. **盲盒（已移除）**：9 盒亮底 → 打乱全翻"?"（全程不显示内容）→ 弧线换位 22 次（含双对同换）→ 凭记忆选盒开奖，2026-09-29 按需求移除（规格见 git 历史，样式文件 blindbox.css 一并删除）。
6. **翻牌（已移除）**：rotateY 3D 翻转 + 虚晃铺垫 + 真实采样分布展示，2026-09-27 按需求移除（规格见 git 历史）；其"旁位真实采样展示"思路由盲盒弹窗后的揭底继承。
7. **老虎机（对对碰）**：三滚轮错峰启动（140/330/520ms）、各自 easeOutCubic 减速（2.4/3.15/3.9s，圈数随时长 +1 保持转速），高速期滚动模糊（blur 2px），逐格 tick；落点格内容提前替换为服务端定的三轴符号，并 clone 一格同内容的复制格接到条带末尾——滚动量恰为整圈，减速滑入视野的是复制格，停定复位 translateY(0) 换回首格，杜绝取模循环带来的空白窗口与跳变。图案全程可见、绝不隐藏（2026-09-30 按需求撤掉蒙版显影）；落定"剪彩"= 滚动 90% 进度挂 `.is-landing`：一道渐变高光伪元素自上而下扫过（550ms）+ 内容亮→正常聚焦脉冲（500ms），首格与复制格同步保证换格无感。每列停定回弹 240ms，末轮停齐后补齐到 5.0s 时机身震动 + 顶灯跑马 + 停格闷响。**连线演出**：中奖轮成对/三条的轴亮灯（is-set）、落单轴压暗（is-dim）；没抽到三轴朴素停格。**超级大奖（三钻连线）**：跑马灯切"★ 超级大奖 ★"金字狂闪、机身金环脉冲、弹窗瞬间全屏彩带双炮 + app.js 收刀琶音换华丽版 `sound.jackpot`；开关在后台（人多时再开）。弹窗支持多奖品（同类合并 ×N）。
8. **结果弹窗**：spring 缩放进场 cubic-bezier(0.34,1.56,0.64,1)；中奖 → 全屏彩带（canvas 物理粒子：重力/阻力/旋转）+ 胜利琶音；谢谢参与 → 灰白纸屑小概率飘落 + 温柔双音，不嘲讽。
9. **可访问性**：`prefers-reduced-motion` 时全部动画压缩为 ≤400ms 淡入淡出；动画期间禁止重复点击。
10. **历史记录**：扭蛋机玩法（含舱内 2D 物理彩球）与翻牌玩法已于 2026-09-27 按需求移除，规格见 git 历史（c13073b 及之前）。
11. **空格键连抽**：document 级 keydown（app.js）——结果弹窗开着 → 空格 = "再抽一次"；否则点当前玩法的开始键（.wheel-hub / .slot-btn 中未禁用且可见者），全程一键连抽。守卫次序：玩法/主题浮层打开不抢空格 → 弹窗分支优先（此时焦点在弹窗关闭钮上）→ 拉杆等自带空格处理的部件在 target 阶段 preventDefault 后 document 层让路（`e.defaultPrevented`，修掉拉杆聚焦双响）→ 按钮/输入聚焦时交还原生行为避免双触发；忽略 e.repeat 与组合键。

### 3.5 音乐时间轴（《中奖概率倍儿高》，8.04s 整曲）

素材：`web/assets/lucky-song.mp3`（碎碎冰翻唱；"停"的实际落点以用户实听为准 ~5.0s，推翻早期响度分析给出的 4.0s 结论；"停"后唱"没中"，7.2s 起哭声）。
共享常量 `web/js/music.js`：`RESULT_AT = 5.0`。

- **起播**：`/api/draw` 返回（结果到手）的瞬间起播并与动画同时开跑——点击到起播仅有本机 API 延迟（~20-50ms），音乐与动画严格同相。
- **没中**：5.0s 各玩法落定结果、弹窗出场，歌继续唱"没中"+哭声直到 8.04s 自然结束（默认"谢谢"合成音效让位，不叠加）。
- **中奖**：5.0s 出结果，歌播到后台配置的收刀点 `win_stop_at`（新装默认 5.5s）快速收刀，收刀后接胜利琶音 + 彩带。收刀点由管理员在后台试听调节（`/admin` → 中奖音效 → 试听到点即停），保存后前台刷新生效；设为小于 5 的值表示揭晓瞬间立即切。
- **历史备注**：曾试过"人声采样叠加/延迟收刀让停字唱完"两轮方案，均因混音里该人声本就不突出而不达意，已全部撤回；最终以"管理员手动定收刀点"为准。
- **快速再抽**：上一首未结束就开新一轮 → 从 0 重启。
- **开关**：工具栏 🎵 独立于 🔊 音效开关，localStorage（`lucky.music`）持久化；`prefers-reduced-motion` 实时读取、不播音乐（动画走各自的快速路径）；自动播放被策略拒绝时动画照常走自有时钟。

## 4. 概率模型（谢谢参与动态转移）

每个奖品：基础权重 `W_i`（后台可改）、总库存 `S_i`、剩余 `R_i`；谢谢参与基础权重 `W_0`。

| dynamic 模式 | 奖品有效权重 | 谢谢参与有效权重 |
| --- | --- | --- |
| `off` 关闭 | `W_i`（`R_i>0`），否则 0 | `W_0` |
| `per_win` 每抽一件渐移（默认，字面语义） | `W_i × R_i / S_i` | `W_0 + Σ W_i × (1 - R_i/S_i)` |
| `depleted` 抽空才整移 | `W_i`（`R_i>0`），否则 0 | `W_0 + Σ_{R_i=0} W_i` |

- `per_win`：每抽走一件奖品，该奖品"一份"的概率即时让给谢谢参与，库存抽空时恰好整体转移完。总概率质量恒定，只做再分配。
- 后台改动基础权重/补货即时生效；补货会让已转移概率自动"回流"（公式由库存推导，无漂移）。
- 已接受的瞬态偏差（2026-09-26 审查确认）：权重基于事务外快照，若并发请求恰逢某奖品被抽空的同一瞬间，该单抽按快照权重计算、偏差下一抽自愈（默认权重 ≤0.6pp，微秒级窗口，单机 kiosk 可忽略；详见 `app/store.py` `draw()` 文档字符串）。

默认权重（后台可改）：棒棒糖 30 / 奶龙 20 / 笔记本 15 / 书签 10 / 鲨鱼匕首 8 / 电子爬宠 6 / 手柄 2 / 谢谢参与 9（合计 100）。

### 4.1 后台的概率可解释性（2026-09-27 增补）

后台针对"调不动/看不懂"重做：库存改为 `− 剩余/总量 +` 步进直改 + 每行"补满"，改动即时生效（串行队列防乱序写库，剩余/总量互相钳制）；`/api/admin/state` 新增 `thanks_bonus` 字段（动态转移量，权重口径），谢谢参与行显示"含转移 +X 权重"，表格下方常驻解释——**权重设 0 概率也不为 0 的来源就是动态转移**（奖品消耗的库存把权重让渡给谢谢参与），要恒为 0 需关闭动态转移。两个易错点已在界面上写明：①"剩余"清零（总量>0）时 per_win 会把该奖品全部权重转给谢谢参与（制造必中局面时应关闭动态转移）；②权重是相对值，概率 = 份额占比，无需凑 100。

## 5. 接口

公开：
- `GET /api/prizes` —— **剩余奖品查询接口**：`{event, prizes:[{id,name,emoji,remaining,total}], total_remaining}`
- `POST /api/draw` —— 抽奖：`{result:"prize"|"thanks", prize:{...}|null}`
- `GET /api/sample?count=7` —— 按当前概率独立采样展示结果（无副作用、不扣库存），供翻牌旁位展示
- `GET /api/meta` —— 活动名 / 日期 / 主题无关信息

后台（请求头 `X-Admin-Token`，token 见 README）：
- `GET /api/admin/state` —— 权重/库存/配置/有效概率/统计
- `PUT /api/admin/weights` —— 批量改权重 + 谢谢参与权重
- `PUT /api/admin/stock` —— 补货/改库存
- `PUT /api/admin/dynamic` —— 动态转移开关 + 模式
- `PUT /api/admin/event` —— 活动名/日期
- `GET /api/admin/history?limit=` / `POST /api/admin/history/reset`

## 6. 技术栈

后端 Python 3.11+ / FastAPI / SQLite（uv 管理）；前端零构建原生 ES Modules + Canvas + CSS 变量主题系统（离线可用，无 CDN）。
